# Сайт trip-track.app: SEO, презентация, вход через Apple и «Мои поездки»

**Дата:** 20 сентября 2026. **Статус:** решения приняты сессией по поручению
владельца («сделай большую работу, я не за ПК»); спорить с ними можно цифрой.

## 1. Цель
Сайт работает на продвижение: находится в поиске по запросам про трекер
поездок / дневник дорог / альтернативу Google Timeline (ru + en), убедительно
показывает приложение и ведёт в App Store. Плюс первая «полезная» функция для
своих: войти через Apple и посмотреть свои поездки на карте (только свои).

## 2. Что мешает сейчас
SPA на Vite без пререндера: поисковик получает пустой `<div id="root">`, один
`<title>` на все страницы, язык переключается `?lang=`/localStorage — у
русской версии нет своего URL, нет `hreflang`, sitemap на 7 адресов без
языков, JSON-LD с выдуманным `aggregateRating` (ratingCount 2). Контент —
три блока и одна цитата.

## 3. Решения
- **Пререндер в статический HTML на сборке** (react-router `createStaticHandler`
  + `renderToString`, без браузера), по маршруту и языку: `/…` (en) и
  `/ru/…`. Каждая страница — свои `<title>`, `description`, canonical,
  `og:*`, `twitter:*`, `hreflang` (en, ru, x-default), `<html lang>`. После
  гидрации всё работает как SPA. nginx: `try_files $uri $uri/index.html
  /index.html`, настоящий 404 (`error_page 404 /404.html`), `immutable` для
  `/assets/`.
- **Языки — в пути**, `?lang=` и localStorage остаются как совместимость и
  редирект на префикс. Переключатель языка меняет путь.
- **JSON-LD честный**: `SoftwareApplication` без `aggregateRating` (появится,
  когда будет реальный счётчик из App Store), `Organization`, `FAQPage` на
  блок FAQ, `BreadcrumbList` на внутренних страницах.
- **Контент под запросы**: главная (герой, «как это работает», атлас-туман,
  места, путешествия, приватность, FAQ, CTA), страницы `features`,
  `google-timeline-alternative`, `fog-of-war-map` — усилить текстом и
  скриншотами (WebP уже есть); новые: `privacy` (политика, нужна и для App
  Store), `press` не делаем.
- **Вход через Apple на сайте**: Apple JS SDK (`usePopup`), `id_token` →
  `POST /auth/login {identityToken, localUserId, deviceName: "web", nonce}` —
  тот же контракт, что у приложения; аудитория — Services ID, который
  владелец добавляет в `APPLE_BUNDLE_ID` через запятую (код бэкенда уже умеет
  список). Бэкенд получает CORS для `https://trip-track.app`.
- **«Мои поездки»** — раздел `/app` (noindex, вне sitemap, `Disallow: /app`
  в robots): список поездок (`POST /trips/list`), карточка с превью маршрута
  (декод `previewPolyline` тем же форматом, что `public/polyline.util.ts` на
  сервере), экран поездки с полным треком на MapLibre (`POST /trips/detail`),
  выход. Только свои данные, ничего публичного нового.

## 4. Что нужно от владельца (после мержа)
1. Apple Developer → Identifiers → Services ID (например `app.trip-track.web`),
   Sign in with Apple включён, привязан к App ID `com.onezee.TripTrack`,
   домен `trip-track.app`, Return URL `https://trip-track.app/app/login`.
2. Прод бэкенда: `APPLE_BUNDLE_ID=com.onezee.TripTrack,app.trip-track.web`.
3. Деплой бэкенда (CORS) и сайта.

**Проверка 2 октября 2026:** публичный `/app/login` открывается в браузере и
показывает экран входа; preflight API от `https://trip-track.app` отвечает
204 с разрешёнными origin и `x-access-token`. Это подтверждает доступность
страницы и CORS, но не конфигурацию Services ID и не успешный вход в
существующий аккаунт. Исправления авторизации ниже проверены локально;
их наличие в опубликованной версии отдельно не подтверждено.

## 5. Как проверить вход локально

Короткий ответ: **полностью — никак**. Sign in with Apple требует, чтобы
`redirectURI` был `https` и вёл на домен, заранее записанный в Services ID;
`http://localhost` Apple не принимает, а `crypto.subtle`, которым считается
хеш нонса, есть только в защищённом контексте. Поэтому проверка делится на
две части.

**Что проверяется локально (всё, кроме самого Apple):**

```bash
cd trip-track-website
npm test          # декодер полилинии, клиент API, форматы, гейт раздела
npm run lint
npm run build
npm run dev       # http://localhost:5173/app → редирект на /app/login
```

Локальные тесты подменяют SDK Apple и ответы API: они проверяют привязку
ответа к попытке входа (`state`), формат nonce, обновление сессии, выход и
обработку сетевых ошибок. Они **не подтверждают** успешный вход через Apple.

Для проверки списка и карты в браузере используем вымышленные поездки и
изолированный локальный API либо перехват запросов тестовым браузером.
Перехват устанавливается **до открытия страницы** и закрывает все запросы
к production API; для фикстуры достаточно вымышленных токенов, которые
сервер никогда не получит. Для локального API нужно задать
`VITE_API_BASE_URL`, поскольку значение по умолчанию ведёт в production.
Реальные токены из телефона, логов или существующей сессии не копируем.
Так можно проверить пагинацию, карту, отметки и ошибки без доступа к
настоящим маршрутам пользователя и без запросов к production API.

На 2 октября 2026 четыре набора тестов авторизации/API/хранилища проходят
локально (28 тестов), также проходят TypeScript и ESLint изменённых файлов.
Это проверка кода, а не живого аккаунта Apple. При запуске под Node 25
встроенное экспериментальное Web Storage может конфликтовать с jsdom;
проверенный обход для этого окружения —
`NODE_OPTIONS=--no-experimental-webstorage npm test`.

**Переменные окружения** (`.env.local`, в гит не едет):

| Переменная | По умолчанию | Зачем |
| --- | --- | --- |
| `VITE_API_BASE_URL` | `https://api.trip-track.app` | локальный бэкенд, например `http://MacBook-Pro.local:3003` |
| `VITE_APPLE_SERVICES_ID` | `app.trip-track.web` | Services ID, если владелец заведёт другой |

**Что проверяется только на домене:**

1. Apple Developer → Identifiers → Services ID `app.trip-track.web`:
   Sign in with Apple включён, привязан к App ID `com.onezee.TripTrack`,
   Domain `trip-track.app`, Return URL **`https://trip-track.app/app/login`**
   (ровно тот, что шлёт клиент: `origin + '/app/login'`).
2. На проде бэкенда `APPLE_BUNDLE_ID=com.onezee.TripTrack,app.trip-track.web`
   — через запятую, не заменой: иначе перестанет проверяться вход с телефона.
3. CORS на `https://trip-track.app` задеплоен.

Реальный вход проверяется только на HTTPS-домене с заранее
зарегистрированным Return URL. Для отдельного тестового окружения можно
использовать зарегистрированный тестовый домен; сам по себе HTTPS-туннель
не заменяет настройки Apple. После входа тем же Apple Account должны
появиться те же синхронизированные поездки, что на телефоне. Сервер ищет
аккаунт по Apple `sub`, не по email: Services ID должен быть связан с тем
же primary App ID. Для входа через `www` необходим его Return URL либо
перенаправление на основной домен до начала авторизации.

**Привязка попытки входа: nonce и state.** В вебе SDK ничего не
хеширует: Apple кладёт в `nonce` то, что дали. Поэтому клиент шлёт
`SHA-256(raw)` в `AppleID.auth.init` и **сырой** `raw` в `POST /auth/login`,
где `AppleAuthService` хеширует его и сравнивает. Перепутаны местами —
каждый вход падает с `INVALID_APPLE_TOKEN` и строкой
`nonce claim mismatch (replay?)` в логах бэкенда; это и есть первое, что
надо смотреть, если вход не пошёл. Формат хеша (нижний регистр hex) держит
`src/app/appleSdk.test.ts`.

Клиент также создаёт отдельный случайный `state` и сверяет его со `state`
ответа Apple до отправки `id_token` серверу. Отсутствующий или чужой
`state` отклоняется; сценарии покрыты `src/app/LoginPage.test.tsx`.
Это соответствует [контракту Apple](https://developer.apple.com/documentation/signinwithapplejs/clientconfigi/state).


## 10. Личная карта и ручной редактор — 2 октября 2026

Следующий этап реализован локально: `/app/trips` стал библиотекой рядом
с большой картой, а `/app/trips/new` — двухшаговым редактором для PRO.
Существующие маркетинговые маршруты и ru/en URL сохранены. В личном
кабинете убраны декоративный курсор и большой маркетинговый footer,
чтобы пространство работало на карту; на телефоне карта/история
переключаются, редактор показывает карту над формой.

Библиотека получает все страницы сводок по 100 записей, объединяет UUID
и допускает продолжение после ошибки. Фильтры локальны и обновляют карту.
Полный трек и отметки запрашиваются только для выбранной поездки.
Пустая история, отсутствие геометрии, отказ WebGL/тайлов и сетевые ошибки
имеют отдельные состояния и повтор. У ручных поездок явно указан источник;
максимальная GPS-скорость не показывается как измеренная величина.

Редактор разделяет маршрут и сведения: поиск/координаты, точки на карте,
перемещение мышью и клавиатурой, перестановка/разворот, затем название,
локальные дата/время, длительность, машина и сохранение. Автомобильная
прокладка требует необязательного ключа Geoapify на API; без него остаётся
явно названное рисование точками. Черновик не хранится на диске, уход
подтверждается, ошибка подписки его не уничтожает. Сохранение через новый
insert-only endpoint идемпотентно и проверяет подписку/машину на сервере.

Apple Developer проверен 2 октября без изменений: Services ID уже включён,
сгруппирован с `com.onezee.TripTrack`, домен и Return URL совпадают с кодом.
Это не заменяет вход реальным пользователем. Условия совместного
выпуска API/сайта/исправленного iOS и оставшиеся проверки — в STATE.md.
