# Безопасность раздела «Мои поездки» (`/app`)

Дата: 20 сентября 2026. Относится к `src/app/**` на сайте trip-track.app.
Раздел показывает человеку ЕГО поездки после входа через Apple; ничего
публичного он не создаёт и не отдаёт.

## Что где лежит

| Что | Где | Живёт до |
| --- | --- | --- |
| `accessToken`, `refreshToken`, имя/почта/эмодзи аккаунта | `localStorage`, ключ `tt.app.session` | выхода из аккаунта |
| `localUserId` (идентификатор браузера, аналог `SettingsManager.localUserId` в iOS) | `localStorage`, ключ `tt.app.device` | переустановки браузера — выход его НЕ стирает |
| Список поездок, трек, отметки | только `useState` в React | закрытия вкладки |
| Фотографии | нигде — их нет ни в `trips/list`, ни в `trips/detail` | — |

Решения, которые за этим стоят:

- **Поездки не кэшируются нигде.** Ни `localStorage`, ни `IndexedDB`, ни
  Service Worker. Каждый запрос идёт с `cache: 'no-store'` и
  `credentials: 'omit'`, поэтому личный маршрут не остаётся ни в HTTP-кэше
  общего компьютера, ни в хранилище сайта. Выход из аккаунта роняет
  состояние вместе с деревом React — стирать отдельно нечего.
- **`localUserId` остаётся намеренно.** Это идентификатор устройства, а не
  секрет: тот же браузер, войдя снова, обязан выглядеть для сервера тем же
  устройством. В нём нет ничего об аккаунте.
- **Токены не в cookie.** В протоколе бэкенда их нет вовсе (`x-access-token`
  как заголовок), поэтому CSRF на этих маршрутах не существует как класс:
  чужой сайт не может заставить браузер приложить токен к запросу.

## Чем это можно сломать и что этому мешает

**XSS → кража токена.** Главный риск: `localStorage` доступен любому
скрипту на origin. Что сделано:

- ни одного инлайнового `<script>` в компонентах раздела и ни одного
  `dangerouslySetInnerHTML` — страница готова к жёсткому CSP;
- единственный сторонний скрипт во всём разделе — SDK Apple
  (`appleid.cdn-apple.com`), и он грузится ЛЕНИВО и только на `/app/login`
  (`src/app/appleSdk.ts`); на списке и на экране поездки чужого кода нет;
- ни одна строка с сервера не попадает в вёрстку: ошибки показываются по
  коду через переводы (`src/app/errors.ts`), текст `message` от бэкенда не
  выводится никогда.

**Что стоит добавить на nginx (не сделано здесь — файл не наш):**

```
Content-Security-Policy: default-src 'self';
  script-src 'self' https://appleid.cdn-apple.com https://analytics.trip-track.app;
  connect-src 'self' https://api.trip-track.app https://appleid.apple.com https://tiles.openfreemap.org;
  img-src 'self' data: blob: https://tiles.openfreemap.org;
  style-src 'self' 'unsafe-inline'; frame-src https://appleid.apple.com;
  object-src 'none'; base-uri 'self'; frame-ancestors 'none'
```

`frame-ancestors 'none'` здесь важнее прочего: без него страницу со списком
поездок можно положить в чужой iframe и обмануть нажатием.

**Время жизни токена.** Своего срока у клиента нет — он полагается на
ротацию refresh-токенов на бэкенде. Клиент делает РОВНО ОДИН повтор с
обновлением на `USER_NOT_AUTH` (и на голый HTTP 401 от прокси), и при
отказе обновления сессия стирается локально (`src/app/api.ts`, тесты в
`api.test.ts`). Параллельные запросы делят одно обновление, иначе два
повтора крутили бы один и тот же refresh и второй ломал бы сессию.

**Аналитика.** Umami подключён глобально тегом в `index.html` и сам
трекает пути, то есть `/app/trips/<uuid>` уехал бы к аналитике как путь
страницы. Раздел ставит документированный флаг `umami.disabled` в
`localStorage` на входе и НЕ снимает его, пока есть сессия (снимает при
выходе и при уходе из раздела без входа) — см. `src/app/analytics.ts`.
Остаточная дыра записана честно: самый первый заход по ссылке на поездку в
браузере, который здесь ни разу не входил, подавить изнутри приложения
нельзя — тег `defer` успевает отправить просмотр раньше нашего кода.
Закрывается это только в `index.html` (`data-auto-track="false"` или
исключение пути), и это владелец файла, не этот раздел. Ссылок на поездку
наружу приложение не даёт: `/app/trips/:id` существует только в истории
SPA, кнопки «поделиться» в разделе нет.

**Индексация.** Каждая страница раздела ставит
`<meta name="robots" content="noindex, nofollow">` на время жизни
(`src/app/meta.ts`), плюс `Disallow: /app` в `public/robots.txt`. Обе
половины нужны: robots.txt просит не ходить, мета — не индексировать то,
что всё-таки открыли.

## Что проверить следующему аудиту

1. CSP выше — реально ли выставлен на nginx и не сломал ли он карту и
   вход Apple (частый промах — забытый `frame-src` для `appleid.apple.com`).
2. `APPLE_BUNDLE_ID` на проде: Services ID добавлен ЧЕРЕЗ ЗАПЯТУЮ, а не
   заменил bundle id приложения, иначе вход с телефона перестанет
   проверяться.
3. CORS на бэкенде: список origin должен быть точным (`https://trip-track.app`,
   `https://www.trip-track.app`), без `*` и без отражения Origin.
4. Не появилось ли где-то в разделе хранение поездок (кэш, оффлайн-режим,
   Service Worker) — правило «личное живёт только в памяти вкладки».
5. Не выводится ли где-то `error.message` с сервера напрямую.
6. Заголовки: `X-Content-Type-Options: nosniff`, `Referrer-Policy:
   strict-origin-when-cross-origin` (чтобы путь с id поездки не уезжал в
   Referer сторонним доменам — тайлы карты грузятся с openfreemap).
7. Ротация refresh на сервере при повторном предъявлении старого токена —
   клиент на это рассчитывает.
