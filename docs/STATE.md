## Условия выпуска

1. **Раздельный выпуск.** Вход через Apple и просмотр поездок выпускаются
   независимо от редактора. На API `WEB_MANUAL_TRIPS_ENABLED` по умолчанию
   false: capabilities отдаёт manualTrips/search/routing=false, а прямые
   create/search/route запросы отвергаются до записи и вызова провайдера.
   Сайт скрывает добавление; прямой URL показывает «скоро». Старая версия
   API или ошибка capabilities также не открывает редактор.
2. **iOS-синхронизация.** В текущем клиенте первый pull новой поездки
   ошибочно может считать Core Data default `pendingUpload` локальной
   правкой и не принять `source=manual`. Кроме того, summary не содержит
   полного трека, а собственная поездка не догружает его при открытии.
   Исправление подготовлено отдельно в рабочей копии
   `../trip-track-web-sync`; его нужно проверить и включить в будущий
   iOS-релиз перед открытием веб-создания поездок для пользователей.
   Сборка 0.8.4 (69), уже находящаяся на App Review, не изменялась.
3. **API.** Выпустить связанные изменения backend до новой версии сайта.
   PRO берётся из серверной проверенной подписки. Локальная подписка
   Sandbox/TestFlight сама по себе не подтверждает PRO на production API;
   не включать приём sandbox-платежей в production ради этой проверки.
4. **Поиск и дороги.** Для полного редактора требуется серверный
   `WEB_GEOAPIFY_API_KEY`, квоты и атрибуция. Без ключа работает режим
   рисования точками и ввод координат. Настройка — раздел 7
   `trip-track-backend/docs/web-login.md`. Реальный вызов провайдера
   с ключом ещё не проверялся.
5. **Сайт.** Вход и просмотр можно публиковать с закрытым редактором.
   Включить `WEB_MANUAL_TRIPS_ENABLED=true` только после совместимого iOS. Локальные
   env override не копируются в Docker; production URL и Services ID
   уже заданы значениями по умолчанию.
6. **Проверка после выката.** На HTTPS-домене войти тем же
   Apple Account, сравнить библиотеку, открыть маршрут; с подтверждённой
   PRO сохранить одну тестовую приватную поездку, дождаться sync на
   исправленном iPhone, проверить источник «вписанная», полный маршрут,
   километры и отсутствие GPS-наград. Затем удалить тестовую поездку
   средствами приложения. Отдельно проверить выход из веб-аккаунта.

2 октября владелец явно разрешил самостоятельный деплой для проверки
живого Apple-входа. Выкладка выполнена штатными CI: backend GitLab master,
website GitHub Actions master. До замены образов сохраняются rollback-теги;
новые записи поездок остаются закрыты сервером. iOS build 69 не меняется.
Успешная сборка CI сама по себе не подтверждает реальный Apple login:
результат входа и совпадение библиотеки фиксируются после живой проверки.

## Ограничение домашней зоны

Домашняя зона iPhone хранится и применяется локально. Веб-редактор её
не получает, поэтому выбранные точки приватной веб-поездки сохраняются
на сервере без этой обрезки. Это явно объяснено перед сохранением и в
политике приватности. Пользователь может не ставить точки внутри зоны;
приватность поездки не означает отсутствие её координат на сервере.
